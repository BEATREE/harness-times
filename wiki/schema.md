# 规则层：写作与制图契约

> 这一页是**约束**，不是教程。它规定「以后新增或修改的任何一章，必须长成什么样」。
>
> 判断标准很简单：**凡是这里写了「必须」的，都有一条脚本或构建期抛错在守着它**。
> 如果你发现某条规则只是文档里的愿望、没有脚本守，请把它降级成建议，或者去 `scripts/wiki-lint.mjs` 里补上断言。

## 一、frontmatter 契约

每章正文的头三行必须是：

```yaml
---
chapter: harness-02-agent-loop      # 必须等于文件名去掉 .md
lead: '一句话导语，斜体大字，出现在页面顶部'
note: '可选的编辑注 / 本版修订说明'    # 可选
---
```

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `chapter` | ✅ | **必须等于文件名**。不等时 `src/pages/[domain]/[slug].astro` 会抛错、构建失败 |
| `lead` | ✅ | 单引号包裹的单行字符串。**不要换行**——YAML 里换行会变成多行折叠，排版会歪 |
| `note` | ⬜ | 有则显示为「编辑注」信息条。用于「本版改了什么」「为什么强调这一点」 |

**⛔ 不要在 frontmatter 里写标题、序号、难度、时长、标签。**
这些的**唯一来源**是 `src/data/curriculum.ts` 的 `CHAPTERS` 数组。
两处都写必然失同步，而失同步时页面只会静默显示错的那一个。

## 二、正文骨架（8 块，顺序固定）

读者已经习惯了每章的结构，新增章节请沿用：

```
1. 导语           ← <p class="dropcap">…</p>   首字下沉段，承接 lead
2. 分节正文       ← ## 一、…  ## 二、…          中文数字小节，每章 7–12 节
3. 图解           ← <figure class="fig">        每章 1 张主图，放在需要「看一眼」的位置
4. 实操代码       ← ```python title="x.py"      每章 ≥1 段，必须能跑，不是伪代码
5. 面试官会怎么问 ← 由 src/data/interview.ts 自动渲染，正文里不要写
6. 自测           ← <div class="quiz">          3 道单选，见第五节
7. 小结 + 金句    ← 列表 + <p class="pull-quote">
8. 参考与延伸     ← ## 末节，外链清单（见第二节之二）
```

小节标题用**中文数字**（`## 一、循环的骨架`），不用阿拉伯数字、不用加粗替代。
每章末尾的 `pull-quote` 是全章最想让人记住的一句，署名固定为 `<cite>本刊编辑部</cite>`。

### 2.1 什么时候该用 `###` 子节

`##` 是「读者想跳着找的那一层」，`###` 是「顺着读时用来喘气的那一层」。判断标准：

- 一节里出现了**两种以上不同的论述动作**（先解释名词、再摊开代价、最后给推论）→ 拆 `###`；
- 一节超过约 1200 字还没换气 → 拆 `###`；
- 只是同一件事的补充说明 → 不要拆，写成段落即可。

`##` 数量上界放宽到 12 就是因为这个：**宁可多两个 `##` 让目录能跳，也不要堆一段三千字的墙。**

### 2.2 参考与延伸（每章最后一节）

固定为 `## ` 最后一节，纯 markdown 列表（**不要用 HTML 块**，否则术语标记与链接都失效）。
要求：

- **数量 5–8 条**，少于 5 条说明这一章没什么可深挖的（那就该合并到别章）；
- 按「先看图 → 再看代码 → 最后读论文」这个**动作顺序**分组，而不是按类型分组；
- 每条格式固定为：`- [标题](url) —— 一句话说清「什么时候该读它」`。**不允许只贴链接。**
- 外链必须**先登记进 `scripts/sources.txt` 的「章级延伸阅读」组**，并跑过
  `node scripts/check-links.mjs --file=scripts/sources.txt`；
- ⛔ **默认不收录在中国大陆打不开的域名**（`en.wikipedia.org` / `huggingface.co` 是已知实例）。
  判定方法：`check-links` 报 `fetch failed`（连不上）而不是 `403`（反爬）→ 视为不可达，换来源。

**术语标记的写法见第十一节**（`[[id]]` 怎么加、什么时候该加）。

## 三、图解规范 ★ 最容易踩坑的一块

### 3.1 外层结构

```html
<figure class="fig">
  <div class="fig-frame">
    <svg viewBox="0 0 660 420" role="img" aria-label="用一句话描述这张图在讲什么">
      …
    </svg>
  </div>
  <figcaption><b>图 1</b>　图注。**加粗的那半句**才是这张图的结论。</figcaption>
</figure>
```

- **`role="img"` + `aria-label` 必填**。SVG 里的 `<text>` 对读屏软件不构成可读内容，
  没有 `aria-label` 的图对屏幕阅读器用户等于不存在。
- `figcaption` 以 `<b>图 N</b>　` 开头（注意是全角空格 `　`），N 是该章的图序号。
- **`viewBox` 必填，且必须写成 `0 0 <宽> <高>`**。
  构建期插件 `src/lib/diagram-motion.mjs` 从 `viewBox` 里读出宽度，
  写成 `--vbw` 内联样式，移动端靠它决定图解的最小宽度（见 3.4）。
  `viewBox` 缺失或格式不对 → 图解标注整段跳过 → 动效与移动端适配全部失效。

### 3.2 图内的排版约定

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 标题字体 | `font-family="Georgia, serif"` | 拉丁走衬线，与站内标题一致 |
| 正文字体 | `font-family="ui-monospace, monospace"` | 图内说明文字走等宽，视觉上「像标注」 |
| 字号区间 | `8.2` – `13` | 标题 `11`–`13`，主标签 `10.8`–`11.5`，说明 `8.7`–`9.8`。**不要低于 8.2** |
| 主文字色（描边/深字） | `#1f1b16` | 墨色 |
| 辅助说明色 | `#6b6257` | 灰褐，用于次要一行 |
| 领域色 | 见下表 | 图内强调色必须取自所属领域 |

**领域配色（与侧栏、领域页一致）：**

| 领域 | 主色 | 浅底 | 典型用途 |
| --- | --- | --- | --- |
| `llm` 大模型原理 | `#2c4a7c` | `#eef1f7` | 模型侧的概念 |
| `harness` Harness 工程 | `#9b2c2c` | `#fbf1f1` | 失败模式、危险路径 |
| `eval` 评测工程 | `#b8944b`（深字用 `#8a6a1e`） | `#fdf6e8` | 指标、口径 |
| `knowledge` 知识引擎 | `#2f6157` | `#eef4f1` | 数据、知识、可信路径 |

**形与底：**

- 有边框的节点：`stroke-width="1.3"` + `fill` 用对应的浅底色。
- 纯底板（无边框的大块说明区）：`fill="#fbf8f2"`。
- 连线：`stroke-width="1.2"`。
- 箭头用 `<defs><marker>` 定义，**`id` 必须在同一页内唯一**（当前约定 `ar1` / `ar2` / `ar3`…）。
  两章之间 id 重复无妨（不同页面），同一页内重复会导致后一个 marker 覆盖前一个。
- `<defs>` 的位置：**新图统一写在 `<svg>` 开标签之后**（紧跟一行）。
  ⚠️ 这里要如实说一句：站内目前两种情况都有，**哪个在前取决于那张图是谁写的**
  （第 1 章那 7 张是 2026-09 新写的，一律前置；早期章节的老图是后置）。
  **两者没有任何功能差别**
  （`diagram-motion` 对 `<defs>` 内的内容一律不动，而 SVG 的 marker 引用不受声明位置影响），
  所以不要为了「统一」单独去改那些老图 —— 那是纯 churn。
  另外 **70 张图里只有 36 张带 `<defs>`** —— 其余 34 张没有箭头连线，根本不需要。
  新图照着第 1 章写即可。
- 图内**不要写空行**——见 3.3，这是最要命的一条。
- ⚠️ **所有 `<text>` 必须落在 `viewBox` 之内。** svg 默认 `overflow: hidden`，
  一行注释字写长一点就会在右边缘被**安静地切掉** —— 构建成功、画面照出，
  只有放大截图才看得出来。`tools/verify.mjs` 第 [12] 节会对**全站每一章**逐个量
  `getBBox()` 守住这条（22 页全扫）。
  写法上留够余量：`font-size="9.6"` 的等宽行，**一个汉字约占 9.6 单位、一个半角字符约 5.8 单位**，
  660 宽的画布从 `x="16"` 起算大约只放得下 55–60 个汉字当量的文字。

**图型分类**（做新图时先想清楚这张图回答哪个问题）见 `design.md` 7.5：
流水线型 / 矩阵型 / 切分型 / 对照型 / 掩码型。**一张图只承担一个论述动作。**

### 3.3 ⛔ 两个会「静默失败」的坑

**坑 A：HTML 块内的空行会腰斩整张图。**

CommonMark 规定「HTML 块遇到空行即终止」。所以：

```html
<figure class="fig">
  <svg …>
    <text …>第一行</text>

    <text …>这一行开始，整个 figure 已经被截断了</text>
  </svg>
</figure>
```

结果：`</figure>` 之前的内容被渲染，之后的内容被当成缩进代码块塞进 `<pre>`。
**页面看起来还在，图却没了**——没有任何报错。

防线：`npm run content:check`（已挂在 `prebuild`）。
写完正文先跑一次；它会指出文件与行号，`npm run content:fix` 可自动删除块内空行。

**坑 B：SVG 空元素丢掉自闭合斜杠 → 整张图消失。**

```html
<rect x="16" y="36" width="150" height="40"/>   ← 对
<rect x="16" y="36" width="150" height="40">    ← 灾难
```

HTML 解析里，`<rect>` 不是可容纳子元素的容器。少一个 `/` 之后，
它后面的所有元素都变成了它的子节点，于是**整张图什么都不渲染**。

防线：`diagram-motion.mjs` 在构建期扫描每个 SVG 行，
发现 `rect|line|circle|path|ellipse|polygon|polyline` 缺少 `/>` 会**直接抛错、构建失败**。
这是刻意设计的「宁可构建失败，也不要静默产出空图」——因为空图只有截图才能发现，
而截图不在 CI 里。

### 3.4 移动端可读性（不能靠「看起来还行」）

图解在设计稿上是 660px 宽的。手机上正文栏只有 ~340px，
如果让 SVG 等比缩到 340/660 ≈ 0.52，图里 9px 的字会变成 4.7px——**完全读不了**。

所以采取的策略是**不让它缩，让它横向滚动**：

```css
/* 基础：不小于设计宽度 */
figure.fig svg { min-width: calc(var(--vbw, 660) * 1px); }

/* 窄屏：再放大一点，并把右边缘提示成可滚动 */
@media (max-width: 1128px) {
  svg { min-width: calc(var(--vbw) * 1.35px); }
  .fig-frame { /* 右缘滚动阴影 */ }
}
@media (max-width: 1128px) and (hover: none) {
  /* 触屏设备追加一行「↔ 图解可左右滑动」提示 */
}
```

这条链路完整依赖 `--vbw`，而 `--vbw` 来自 `viewBox`（见 3.1）。
**所以 viewBox 缺失 = 移动端图解不可读**，这是同一个 bug 的两种表现。

⚠️ **不在 markdown 管线里的内联图**（例如 `src/pages/index.astro` 的能力地图）
不会被插件标注，必须**手写** `style="--vbw:680"`，否则移动端适配失效。

### 3.5 图解动效（由插件自动加，不要手写）

`diagram-motion.mjs` 在构建期给 SVG 标注这些 class，样式在 `global.css` 里：

| class | 加在什么元素上 | 表现 |
| --- | --- | --- |
| `dm-svg` | `<svg>` | 容器钩子，同时写入 `--vbw` |
| `dm-n` | 有描边的 `rect`/`circle` | 描边从细到粗的「扫读」脉冲，表达阅读顺序 |
| `dm-plate` | 无描边的底板 | 同上，弱化版 |
| `dm-t` | 所有 `<text>` | 按 `--i` 错峰淡入（每 22ms 一级，最长 760ms） |
| `dm-go` | 箭头线（构造成 `<line class="dm-go">`） | 沿 `--len` 走的「流向彗星」，`stroke-dashoffset` 动画 |

**写正文时不需要做任何事**——不要手写这些 class，不要手写 `--i` / `--len` / `--sw`。
插件会算。手动加反而会被覆盖或算错。

无箭头只有分层的图（如知识建模）靠 `dm-n` 的扫读脉冲表达顺序；
有箭头的流转图额外多一层彗星。两种情况要表达的是同一件事：**读这张图的顺序**。

`@media (prefers-reduced-motion: reduce)` 下所有动效关闭、彗星层置 `opacity:0`。
**新增动效时不要忘记把这个降级分支一起写上。**

## 四、代码块规范

````markdown
```python title="agent_loop.py"
# 代码
```
````

- **`title="…"` 必填**。文件名栏是这个站的视觉识别点之一，缺了它代码块会退化成一个光秃秃的 `<pre>`。
  实现原理（Shiki transformer + rehype 插件「接力」）在根 `README.md` 里，改之前务必读。
- 语言标签目前**只用 `python`**（22 段全部是 Python）。
  引入新语言没问题，但要先确认 Shiki 已加载该语法高亮。
- 代码必须**可直接运行**，不是伪代码。宁可短，也要能跑。
- 代码里的注释用中文，但**变量名与输出字符串保持英文/ASCII**——
  中文变量名会和等宽字体配合得很糟。

## 五、信息盒、三线表、自测题

### 5.1 信息盒（正文用到的共 43 个）

```html
<div class="box box-key">      <!-- 关键结论：15 个 -->
<div class="box box-practice"> <!-- 实操提示：15 个 -->
<div class="box box-warn">     <!-- 警告/反直觉：13 个 -->
  <div class="box-title">标题</div>
  <p>正文…</p>
</div>
```

三种盒子各有语义，**不要用 `box-warn` 装普通提示**——读者是靠颜色区分「这句要小心」的。

### 5.2 三线表（正文用到的共 45 个）

```html
<div class="tbl-wrap">          <!-- 必须包在外面：窄屏横向滚动靠它 -->
  <table class="news">          <!-- news 是三线表样式 -->
    <thead><tr><th>列</th>…</tr></thead>
    <tbody><tr><td>值</td>…</tr></tbody>
  </table>
</div>
```

**`tbl-wrap` 不能省。** 表在手机上必然超出正文栏，没有这层包裹就只能整页横向滚动。

### 5.3 自测题（每章 3 题，共 66 题）

```html
<div class="quiz">
  <div class="quiz-head"><span>本章自测</span><span>答错的题请回看第 N 节的表格</span></div>
  <div class="q-item" data-qid="llm04-q1" data-answer="1">
    <div class="q-text"><span class="idx">Q1</span>题干？</div>
    <button class="opt" data-i="0"><span class="tick">A</span><span>选项</span></button>
    <button class="opt" data-i="1"><span class="tick">B</span><span>选项</span></button>
    <button class="opt" data-i="2"><span class="tick">C</span><span>选项</span></button>
    <button class="opt" data-i="3"><span class="tick">D</span><span>选项</span></button>
    <div class="explain"><b>B。</b>解析，并说明**为什么错的选项错**。</div>
  </div>
  …
</div>
```

| 属性 | 规则 |
| --- | --- |
| `data-qid` | `<领域前缀><章号>-q<题号>`，如 `llm04-q1`、`harness02-q3`。**全站唯一**，进度存储用它做键 |
| `data-answer` | 正确选项下标，**0 起**（`0` = A） |
| `data-i` | 该选项下标，必须 0/1/2/3 齐全且与 `data-answer` 对应 |
| `class="tick"` | 固定显示 A–D 的圆形标记 |
| `.explain` | **必须写**。解析的价值不是重复答案，而是解释**干扰项为什么错** |

> ⚠️ `data-qid` 一旦上线就**不要改**：它已经写进读者的浏览器 localStorage 里了。
> 改了会导致老读者的答题记录错位。要改就新加一道题。

| 禁止 | 为什么 |

## 十一、名词卡片与讲解标准

> 这一节是 2026-09 新增的。起因很具体：有读者反馈「第一章讲 Transformer，
> 底下直接开始讲公式和形状，但什么是张量、什么是投影、投影的输入输出是什么，
> 一个都没解释」。这不是某一章的问题，是**全站的讲解顺序问题**，所以立成契约。

### 11.1 三类落点，一份数据

术语的解释**只在 `src/data/glossary.ts` 里写一次**，三个地方共用：

| 落点 | 由谁渲染 | 读者怎么到达 |
| --- | --- | --- |
| 正文行内标记 | `src/lib/glossary-terms.ts`（remark 插件，构建期把 `[[id]]` 展开成 `<a class="term">`） | 正文里点到虚线底的词 |
| 章节页弹窗 | `TermCard.astro`（把本章用到的卡片渲染进隐藏容器，点击时搬进弹窗） | 同上；无 JS 时退化为跳到名词库锚点 |
| `/glossary/` 名词库页 | `glossary.astro` + `TermCardBody.astro` | 侧栏「名词库」、或任意术语链接的兜底目标 |

**卡片本体只有一套模板**（`TermCardBody.astro`）。弹窗与名词库页各写一套的话，
字段顺序、外链 `rel`、图例尺寸迟早会不一致，而这种不一致没人会发现。

### 11.2 正文里怎么写

```
[[tensor]]               → 渲染成「张量」，指向 /glossary/#t-tensor
[[scaling|缩放]]          → 用自定义显示文字
```

- ⛔ **`[[id]]` 只能出现在 markdown 文本里**（段落、列表、引用、`###` 标题）。
  写进 `<figure>` / `<div class="box">` / `<table>` 这类**原始 HTML 块里不会展开**，
  页面上会原样显示 `[[tensor]]` —— 而且**构建不会失败**，只能靠人眼发现。
- id 查不到时 remark 插件**直接抛错让构建失败**（fail-loud），并打印全部可用 id。
- 同一个名词在一章里**只标第一次**（含 `##` 标题之前的导语部分）。满页虚线底会把正文读成斑马线。
- 表格里要用术语时，写普通文字，不要用标记。

### 11.3 什么时候该新增一个名词

满足**任意一条**就收：

1. 它是一个**读者可能不认识的名词**，且不在常识范围内；
2. 它在本站**跨章出现**——同一个词在 3 章里都要用，就该有一条卡片；
3. 它的**常见误解会造成实质性错误判断**（`[[context-window]]`、`[[causal-mask]]` 属此类）。

⛔ 不要收：产品名（LangChain）、纯 API 名（`create_chat_completion`）、
只在某一章出现一次且不影响理解的细节术语。

### 11.4 卡片的字段契约

`Term` 的字段顺序就是卡片上的展示顺序，按 `src/data/glossary.ts` 的类型定义写：

`id` · `term` · `en?` · `aliases?` · `naming?` · `meaning` · `scene` · `domain` · `explain` · `example?` · `figure?` · `refs?`

三条硬要求：

- **`meaning` 必须一句话说清「它是什么」，且不出现别的未解释名词。**
  这一句也是行内链接的 `title`（鼠标悬停就能看到），所以它得能独立成立。
- **`scene` 回答「我会在哪撞见它」**，不是重复 `explain`。写具体场景，不写「常用于深度学习」。
- **`refs` 的每条 `why` 要说清「什么时候该读它」**。禁止「点击查看详情」这类无信息量的话；
  也禁止只贴链接不写理由（`wiki-lint` 之外靠本条约定的自觉）。

#### 11.4.1 `naming`：中文译名丢了什么

**这一条是 2026-09-18 加的，起因是一次真实的读不懂**：正文里的「前向」是什么？
它其实是 `forward pass` 的直译，而同一批英文资料里还有个 `feed-forward` 被译成「前馈」——
**英文里是两个词，中文都塌成了「前/向/馈」这几个字**，读者因此分不清
「一次计算」（过程）和「一层网络」（结构）。

所以凡是**中文译名会盖住原始命名、或者一词多译**的名词，都要补 `naming`：

- 写清**它从哪个英文词来**（`forward pass` / `feed-forward`）；
- 写清**直译时丢了什么**（"pass 是过程、network 是结构"）；
- 点出**最容易和谁混**（feed-forward / backward pass）。

排版上 `naming` 排在「出现场景」之后、`explain` 之前，左侧有一条竖线、
键名与正文同款；里面用 `<b>` 标出真正区分的那几个词（**不能用 `**`**，理由见 11.4 结尾）。

⛔ 不要给每条都硬凑一个 `naming`。**译名没丢东西的名词不写**——
`naming` 只在「中文成了理解障碍」时才写。判断标准一句话：
**把中文换成英文，读者会不会恍然大悟？会，就该写。**

#### 11.4.2 英文原名由构建期注入，不要手写

正文里**不要**自己写「（Forward pass）」这种注解。构建期插件
（`src/lib/glossary-terms.ts`）会在**本章第一次**出现该名词时，
自动在链接**后面**补一个 `<span class="term-en">（英文）</span>`：

```
[[forward|前向]]  →  前向</a><span class="term-en">（Forward pass）</span>
```

原因有两个，缺一不可：

1. **「首次」这件事只该有一个裁判。** 手写的话，同一章里前后两处谁算「首次」
   取决于作者当时记得什么；构建期注入则以文档顺序为准，同一章同一名词**必只注一次**。
2. **放在链接外面**（不是里面）——点得动、带虚线底的只有中文那一段。
   英文注解塞进链接里会连它一起变成「可点击的术语」，读者点英文也会弹卡片。

`en` 字段为空的名词不注入；`en` 已包含在显示文字里的（如 `[[big-o|大 O 记号]]`）也不重复注入。

### 11.5 正文术语是红色的

行内术语（`a.term`）用套色红 `--red` + 虚线底线，**不跟正文同色**——
这来自一条明确要求：「有单词卡的文字要更容易看到和辨识」。

⚠️ 对比度是**实算**的，不是凭感觉调：`scripts/verify-build.mjs` 里有一条断言，
从 CSS 里读出 `--red` 与 `--paper` 现算一遍，要求纸面 ≥ 4.5:1（当前 6.57:1）。
顺手改深/改浅 `--red` 会直接让这条断言变红，而不是让正文悄悄变难读。

配套的两条无障碍约定：

- 不能只靠颜色区分：红线**同时**带虚线底线，`a.term:focus-visible` 另有 2px 红描边；
- 「已掌握」状态用青绿 `--teal` 而不是红 —— 红色在本站是链接与重点，
  用它表示「完成了」会让人以为还能点走。

### 11.6 学习跟踪：`mark as mastered`

每张卡片的底栏（`.tc-foot`）有一个「标记已掌握」按钮，状态**只存在本机**
（同一个 `ht:progress:v1`，不开新 key —— 理由同 `progress.ts` 的注释：
多一个 key 就多一个「导出备份漏掉了什么」的机会）。

存储契约：

| 位置 | 形状 | 说明 |
| --- | --- | --- |
| `ht:progress.v1` → `terms` | `{ [termId]: { known: true, at: '<ISO>' } }` | **顶层**，不在章节下 —— 词是跨章复用的，掌握度跟着词走 |
| 取消标记 | **整条删掉**，不写 `known: false` | 存储里只留真正掌握过的词；`knownTermIds()` 因此不用过滤，也不会攒空行 |

三个必须同时成立、少一个就会「看起来正常但其实坏了」的环节：

1. **点击 → 落盘**（`toggleTermKnown`）；
2. **落盘 → 界面**：同一页有 25 个按钮，任一变化要 `paintAll()` 全量刷新，
   并监听 `ht:progress` 事件（别的组件、比如进度页导入备份，也会写这份存储）；
3. **刷新 → 读回**：只写不读的实现和「写了但读不回来」长得一模一样，只能靠刷新验证。

⚠️ 弹窗里这条底栏是 `position: sticky; bottom: 0`：卡片正文普遍比面板高
（「张量」那张要滚 1000+px），不钉住的话弹窗里最常用的动作会藏在滚动条尽头
（实测 4 张卡里 3 张看不见）。`tools/verify.mjs` 有一条断言专门盯这件事。
名词库页的卡片**不钉**（那是正常文档流，钉上去会盖住下面的卡片）。

### 11.7 断言在哪里

| 断言 | 位置 |
| --- | --- |
| 章节页的术语链接都指向 `/glossary/#t-` | `scripts/verify-build.mjs` |
| `glossary.ts` 的 id 不重复、字段齐全（含 `meaning` / `scene` / 每个 ref 有 `why`） | `scripts/verify-build.mjs` |
| 名词库页存在，且卡片数与 `TERMS.length` 一致 | `scripts/verify-build.mjs` |
| 弹窗带焦点陷阱、Esc 关闭、`prefers-reduced-motion` 降级 | `scripts/verify-build.mjs`（查源码字符串） |
| 英文原名只在本章首次注入、且挂在链接**外面** | `scripts/verify-build.mjs` |
| 每张卡片都渲染出「命名」行，条数与 `naming` 字段数一致 | `scripts/verify-build.mjs` |
| 术语红与纸面对比度 ≥ 4.5:1（从 CSS 现算） | `scripts/verify-build.mjs` |
| 掌握标记的写入 / 取消 / 筛选 / 刷新读回 | `tools/verify.mjs`（真点击） |
| 弹窗里「标记已掌握」不用滚动就能看到 | `tools/verify.mjs` |
| `[[id]]` 写错时构建失败 | `src/lib/glossary-terms.ts`（构建期抛错） |

⚠️ `meaning` / `scene` / `explain` / `example` 是**走 `set:html` 的内联 HTML**，
markdown 语法在这里**不会被解析**。加粗写 `<b>`、行内代码写 `<code>`，
⚠️ **不要写 `**加粗**`**——它会原样显示成两个星号。

### 11.8 讲解顺序标准（比卡片更重要的一条）

**凡是用到一个名词，读者必须能在此前 3 屏内找到它的解释。** 具体做法：

1. **先名词、后公式。** 一章里若某节要出现形状或公式，它前面必须有一节先把名词说清
   （第一章的第二节就是这一节的样板：不出现任何公式，只解释七个名词）。
2. **每个机制都回答三个问题**：输入是什么（含形状）→ 输出是什么（含形状）→ **为什么会需要这一步**。
   第三条最容易漏，也最关键——「为什么」缺了，读者只会得到一堆记住就忘的步骤。
3. **数量级一定要给例子。** 说「平方增长」不算讲清，要给
   「n 从 8k 到 32k，代价约 16 倍」这种能对上号的数字。
4. **推论要落到工程判断上。** 原理讲完必须回答「所以我在 Harness 里该怎么做」，
   否则这一节属于可以删掉的内容。
