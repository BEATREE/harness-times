# Harness Times · 迭代进度看板（tasks）

> 这一页记「22 章的内容完善做到哪一步了」。
> 与 `wiki/index.md` 的分工：`index.md` 记**有什么**（目录与体量统计），本页记**还差什么**（逐章完善度 + 待办）。
>
> 起因：早期正文太精简 —— 第 1 章开头直接讲公式和形状，读者并不知道「张量」「投影」「打分」各指什么、
> 为什么要有它们。于是给每章补了五件事（见第一节）。第 1 章先做样板，然后铺到其余 21 章。

---

## 一、这一轮要做的五件事

| # | 工作 | 判据（`scripts/tasks-facts.mjs` 数得出来的） |
| --- | --- | --- |
| 1 | 双语名词卡 | 正文用 `[[id]]` 标出 **≥8** 个术语；某名词在**本章首次**出现时由构建期自动补英文原名；卡片含「命名辨析」一栏 |
| 2 | 图解 | **≥3** 张手写 `<svg>`（规矩：一张图只承担一个论述动作） |
| 3 | 常见误区与追问 | 独立小节，**≥4** 条 |
| 4 | 参考与延伸 | 独立小节，**≥3** 条外链，且每条都登记在 `scripts/sources.txt` |
| 5 | 自测题 | **3** 道（`data-qid`） |

配套：题库每章 2–3 问 → 全站 **72 → 134 问**。

**为什么是这五条**：1、3、4 直接对应「名词库 + 词卡 + 外部引用」这条主线；
2 治的是「纯文字讲抽象机制」；5 是对面试价值的兜底。五项都不是风格偏好，脚本数得出来，所以能当判据。

## 三、已知缺口（人工维护，下一轮候选）

这些是这轮各章撰写过程中**已发现、但没在这一轮补**的点。留着，别丢：

| 位置 | 缺什么 | 为什么值得补 |
| --- | --- | --- |
| `eval-01-first-principles` | 显著性检验（McNemar / bootstrap）的判定口径 | 「两个模型差 3 个点算不算提升」是评测岗的必答题，现在只讲了「要控制变量」 |
| `llm-02-kv-cache` | 缓存计费口径（命中/未命中如何计价、prefix cache 的账单差异） | 工程上真正决定「上不上缓存」的是账，不是显存 |
| `harness-08-long-horizon` | 上下文压缩与 prefix 成本的权衡 | 压缩省 token 但破坏 prefix cache，是一组反直觉的取舍 |
| 跨章 | 若干「画不出来」的抽象概念（All-to-All 通信拓扑、闭环评测漏斗） | 需要新图型，现有五类图型（流水线/矩阵/切分/对照/掩码）覆盖不到 |
| `src/data/glossary.ts` | 3 条术语未被任何正文引用：`lenient-parsing`、`prefix-fingerprint`、`repetition-penalty` | 要么在 `llm-04` / `llm-02` 里给它们一个落点，要么删掉 —— 词库里躺着没人点的卡片是噪音 |
| 全站 | 用户提过的「重编为 40+ 章」尚未启动 | 等第 1 章样板风格确认后再动结构 |

## 四、怎么用

```bash
node scripts/tasks-facts.mjs           # 看逐章进度 + 缺口汇总
node scripts/tasks-facts.mjs --md      # 只输出表格（想手动贴时用）
node scripts/tasks-facts.mjs --write   # 改完正文后刷新本页的自动区
node scripts/wiki-lint.mjs             # 核对本表与实测一致
```

**增删判据**：五项工作是「这一轮」的目标，不是永久契约。要改阈值就改
`scripts/tasks-facts.mjs` 顶部的 `CRITERIA` —— 阈值只有一个出处，本页第一张表只是它的自然语言说明。
改了阈值记得回来同步这张表，否则「文档说的」和「脚本查的」会分开。
